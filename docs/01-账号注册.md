# 第一步：开三个账号

这一步**不需要写代码**，全部是网页操作。三个账号互相独立，可以并行开。

预计耗时：Supabase 约 10 分钟，阿里云百炼约 15 分钟（含实名认证）。

做完之后你手上会有 **4 个字符串**，后面所有步骤都要用。先建一个记事本把它们存起来：

```
① DATABASE_URL         = postgresql+psycopg://postgres.xxxx:密码@xxx.pooler.supabase.com:5432/postgres
② SUPABASE_URL         = https://xxxxxxxx.supabase.co
③ SUPABASE_SERVICE_KEY = eyJhbGciOi...
④ DASHSCOPE_API_KEY    = sk-xxxxxxxxxxxxxxxx
```

> ⚠️ 这四个是密钥，**不要发到群里，不要提交到 GitHub**。
> 如果泄露了，去对应平台删掉重建一个即可。

## 一、Supabase（托管数据库 + 图片存储）

### 1. 注册

打开 https://supabase.com ，点右上角 **Start your project**，
用 **GitHub 账号**登录（没有 GitHub 就先用邮箱注册一个，后面阶段四还要用 GitHub 做自动打包）。

### 2. 创建项目

登录后点 **New project**，填三项：

| 字段 | 填什么 | 注意 |
|---|---|---|
| Organization | 默认就行 | |
| Name | `fridge-prophet` | |
| Database Password | **自己生成一个强密码** | ⚠️ **一定要立刻复制存下来**，后面连接数据库要用，关掉就再也看不到了 |
| Region | **Southeast Asia (Singapore)** | ⚠️ 一定要选这个，离国内最近，其他节点会明显变慢 |
| Plan | Free | |

点 **Create new project**，等 2 分钟左右（状态从 `Setting up project` 变成 `Active`）。

### 3. 拿数据库连接串（→ 变量 ①）

左侧 **Project Settings**（齿轮图标）→ **Database** → 往下滚到 **Connection string** → 选 **URI** 标签页。

你会看到类似这样一行：

```
postgresql://postgres.abcdefghijkl:[YOUR-PASSWORD]@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres
```

要做**两处修改**：

1. `[YOUR-PASSWORD]` 替换成你第 2 步设的数据库密码
2. 把开头的 `postgresql://` 改成 **`postgresql+psycopg://`**

改完长这样（这就是变量 ①）：

```
postgresql+psycopg://postgres.abcdefghijkl:你的密码@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres
```

> 💡 **密码里有特殊字符怎么办？** 如果密码里有 `@ # % & /` 这些符号，必须做 URL 编码：
> `@` → `%40`，`#` → `%23`，`%` → `%25`，`/` → `%2F`，`&` → `%26`
> 嫌麻烦的话，最简单的办法是回第 2 步重新生成一个**只含字母和数字**的密码。

> 💡 **端口 5432 还是 6543？** 我们是常驻服务器，用 **5432**（Session pooler）。
> 6543 是给 Serverless 用的，不适合我们。

### 4. 拿 Project URL 和 Service Key（→ 变量 ②③）

左侧 **Project Settings** → **API**：

- **Project URL** → 复制，这就是变量 ② `SUPABASE_URL`
- **Project API keys** 里找 **`service_role`** 那一行，点 **Reveal** 再复制 → 变量 ③

> ⚠️ **绝对不要用 `anon` key 当 service key，也绝对不要把 `service_role` 写进 Android App。**
> `service_role` 是管理员权限，能绕过所有安全规则读写整个数据库，只能放在后端服务器上。
> Android 端要调 Supabase 的话，用 `anon` key。

### 5. 建图片存储桶（可选但建议）

左侧 **Storage** → **New bucket**：

- Name 填 `fridge-photos`
- 把 **Public bucket** 开关**打开**（这样照片才能被公开访问）

> 其实不建也行——后端启动时会自动帮你创建。手动建只是让你心里有数。

### 6. ⚠️ 免费版最大的坑：闲置 1 周会暂停

Supabase 免费版规定：**项目连续 7 天没有任何请求就会被暂停**。

暂停后不是数据丢失，但需要你手动去控制台点一下恢复，恢复要等几分钟。
**如果这件事发生在比赛演示前 10 分钟，就完了。**

三个应对办法，建议全做：

1. **比赛前 3 天起，每天手动打开一次 Supabase 控制台**（打开就算活动）
2. **让后端服务定期访问数据库**——部署上线后后端一直在跑，天然就不会闲置
3. **让我给你配一个定时任务**，每天自动发一次请求保活（需要项目建好之后才能配）

> 顺带说清楚免费版额度，够我们用：
> 数据库 500 MB · 存储 1 GB · 月活用户 5 万 · 带宽 5 GB/月 · 日志保留 1 天
> 我们这种比赛项目，500 MB 数据库能存几十万条食材记录，完全够。

## 二、阿里云百炼（通义千问 API）

### 1. 注册并实名认证

- 注册：https://account.aliyun.com/register/qr_register.htm
- 如果提示未实名，去认证：https://help.aliyun.com/zh/account/verify-your-identity-individual-account
  （个人认证刷脸，几分钟搞定。**不实名无法调用大模型**）

### 2. 开通百炼

用**主账号**打开 https://bailian.console.aliyun.com/model/market

- 会弹出服务协议，勾选同意 → 自动开通
- **如果没弹协议，说明已经开通了**，直接下一步

### 3. 创建 API Key（→ 变量 ④）

打开 https://bailian.console.aliyun.com/model/settings/api-key

点 **创建 API Key** → 起个名字比如 `fridge-prophet` → 确定 → **立刻复制**。

> 创建时**不需要选模型**，调用哪个模型是在代码里指定的。
> 权限建议保持默认的「全部」，如果选了「自定义」要记得勾上 `qwen-vl-max` 和 `qwen-plus`。

### 4. 确认模型可用

打开模型广场 https://bailian.console.aliyun.com/model/market ，搜索确认这两个模型能调用：

- **`qwen-vl-max`** — 视觉识别，负责「看冰箱照片认出食材」
- **`qwen-plus`** — 文本生成，负责「根据库存写菜谱」

> 💡 想省钱可以把 `qwen-vl-max` 换成 `qwen-vl-plus`（便宜不少，识别家常食材够用），
> 或者把 `qwen-plus` 换成 `qwen-turbo`。改 `.env` 一行就行，代码不用动。

### 5. ⚠️ 关于接口地址

百炼现在**按地域提供不同地址**。`.env` 里默认填的是通用地址：

```
AI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
```

如果自检脚本报网络错误或 404，说明你的账号需要用带业务空间 ID 的地址。
业务空间 ID 在这里查：https://bailian.console.aliyun.com/cn-beijing/settings/workspace

然后改成：

```
AI_BASE_URL=https://你的业务空间ID.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
```

**不用自己试**——填好 Key 之后跑一下自检脚本，它会告诉你地址对不对：

```bash
cd backend
.venv/Scripts/python.exe scripts/check_ai.py
```

### 6. 关于费用

新用户开通有免费额度，具体额度以控制台「费用与成本」页面显示为准。
额度用完后按量计费，出账周期是分钟级。

我们项目的调用量估算：

| 场景 | 消耗 |
|---|---|
| 一次冰箱识别 | 1 张图 + 约 500 token |
| 一次菜谱生成 | 约 1500 token |
| 一次完整演示 | 约 5 次识别 + 5 次菜谱生成 |

比赛期间放开用也就几块钱的量级。**但一定要去费用中心设个消费预警**，
避免被刷或者调试时死循环把额度烧光。

## 三、腾讯云（阶段三才用，现在可以先不买）

阶段三部署时再弄，现在只是让你知道要准备什么：

1. 注册 https://cloud.tencent.com/ ，做实名认证
2. **学生认证**（如果你是学生）能便宜很多
3. 买 **轻量应用服务器**，地域选 **中国香港**（免备案），配置 2核2G 起步
4. 操作系统选 **Ubuntu 22.04** 或 **Debian 12**

> 💡 为什么选中国香港而不是上海/北京？
> 大陆节点要用 80/443 端口必须**域名备案**，备案流程约 2 周。
> 香港节点**不需要备案**，可以立刻用，国内访问速度也完全够演示。

## 做完之后

```bash
cd backend
cp .env.example .env
# 用记事本或 VS Code 打开 .env，填入那 4 个变量
```

```bash
# 检查数据库能不能连上、表建好了没
.venv/Scripts/python.exe scripts/check_supabase.py

# 检查 AI 密钥能不能调通
.venv/Scripts/python.exe scripts/check_ai.py
```
