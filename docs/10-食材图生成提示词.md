> **先说明一件事**：当时生成那 40 张图时，**提示词原文没有保存下来**
>（是直接调用工具生成的，没落脚本也没记进文档）。
>
> 所以这份文档是**从成品图反推**出来的 —— 我把现存的 40 张图看了一遍，
> 归纳出实际使用的风格，整理成可复用的模板。
> 用它生成的新图**和现有 40 张风格一致**，可以直接混在一起用。
>

## 一、成品图的风格（反推结果）

对照 `outputs/ingredient-real-photo-contact-sheet-full.jpg` 逐张看，特征如下：

| 特征 | 具体表现 |
|---|---|
| 背景 | **无缝纯白**，看不到桌面/布纹，也没有地平线 |
| 投影 | 主体正下方一团**柔和投影**，让食材「落在平面上」而不是飘着 |
| 构图 | **单个主体、居中、正方形（1:1）**，四周留白均匀 |
| 光线 | 明亮均匀的**摄影棚柔光**，没有硬阴影、没有明显方向性 |
| 角度 | 大多为**略微俯视**（约 30°）或正面平视 |
| 状态 | **生食材原样**。不切配、不摆盘、不加餐具道具 |
| 例外 | 牛奶是**瓶装**、酸奶是**碗装** —— 因为这两样本身就是容器商品 |
| 画质 | 高清、焦点锐利、细节清楚（能看清肉的大理石纹、西兰花的颗粒） |

**核心定位：电商产品图。** 不是美食摄影（那是菜谱图的标准，有木桌、有热气、有摆盘），
也不是插画。就是「一个食材摆在白底上拍一张」。

---

## 二、通用模板

任何文生图工具都能用。**只换主体描述，风格后缀一个字都别动** ——
动了整批图就会看起来像拼凑的。

```
Professional e-commerce product photograph of {主体描述}, single item,
centered on a seamless pure white background, soft shadow directly beneath,
bright even studio lighting, sharp focus, high detail, square composition.
No text, no watermark, no people, no hands, no props, no plate, no bowl,
no table surface, no horizon line.
```

### 中文版（有些工具中文更准）

```
电商产品摄影风格：{主体描述}，单个主体，居中放置在无缝纯白背景上，
正下方有柔和投影，明亮均匀的摄影棚光线，焦点锐利，细节清晰，正方形构图。
不要文字、不要水印、不要人物、不要手、不要道具、不要盘子、不要碗、
不要桌面、不要地平线。
```

### ⚠️ 负面约束必须写全

`no text / no watermark / no people / no hands` 不写的话，
很容易生成带文字水印、或者画面里冒出一只手拿着食材的图。

`no plate / no bowl / no props / no table surface` 是**食材图特有的要求** ——
不写的话模型会习惯性给你摆盘，那就变成菜谱图了，放进冰箱列表里很违和。

## 三、参数

| 项 | 值 | 说明 |
|---|---|---|
| 尺寸 | **1024×1024** | 和现有 40 张一致，正方形 |
| 数量 | 每样 **1 张** | 不用多生成，选最像的 |
| 格式 | PNG | 后续导入脚本会自动转 JPG |

> **为什么最后会变成 512×512**：冰箱列表里的缩略图只有 44dp 见方，
> 3x 屏也才 132px。512 已经非常宽裕（还给以后放大留了余地）。
> 按 1024 存是纯浪费流量 —— 40 张图每张多背几百 KB。

## 五、生成之后的导入流程

**详细步骤见 `docs/09-食材配图扩充方案.md`**，这里只说要点：

```
.tmp-images-ingredients/
    avocado/       xxx.png     →  backend/static/ingredients/avocado.jpg
    blueberry/     yyy.png     →  backend/static/ingredients/blueberry.jpg
```

**目录名必须等于 key**（不要靠顺序对应 —— 顺序一错就会出现
「牛油果配了蓝莓的图」这种不报错、极难发现的问题）。

然后：

```bash
cd backend
python ../tools/import-images.py --kind ingredients --check   # 先看缺什么
python ../tools/import-images.py --kind ingredients           # 真正转换
```

脚本会自动：PNG → JPEG（长边 512、质量 86）、RGBA→RGB、只缩不放。

> ⚠️ **用外部程序生图的话，`.tmp-images-ingredients/` 这个目录结构和 key 命名
> 一定要照做** —— 导入脚本靠目录名认 key。图对了但目录名不对，等于白生成。

## 六、风格一致性怎么检查

生成完之后，**做成一张带标签的拼图看一眼**，别逐张点开
（逐张要读 N 次图，很费时间）。标签写在图**下方**，不要叠在图上。

重点看三件事：

1. **背景是不是都纯白** —— 有几张偏灰或带纹理，整批就不齐
2. **投影是不是都在正下方** —— 有的在左有的在右，看起来像两批图
3. **有没有意外道具** —— 冒出盘子、手、水印的，重生成那一张

## 七、和现有 40 张放一起会违和吗

**不会**，只要风格后缀照抄。现有 40 张的构成：

- 36 张是这套模板生成的（`milk` `yogurt` `cheese` `chicken` … `seasoning`）
- 4 张是用户提供的真实照片（`egg` `lettuce` `cabbage` `broccoli`）

所以这批图本身就是「生成图 + 真实照片」混着的，风格容差比较大。
新生成的图只要遵守「纯白底 + 单个主体 + 柔和投影」，混进去看不出来。
