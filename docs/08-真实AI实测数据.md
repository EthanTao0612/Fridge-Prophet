# 08 · 真实 AI 实测数据

2026-09-29 配好阿里云百炼的 API Key 之后，用**真实模型**（不再是 MOCK）跑了一遍。
这一份记下实测的耗时和效果 —— **演示彩排时要照着这些数字安排节奏**。

---

## 一、耗时（最重要）

| 操作 | 实测耗时 | 说明 |
|---|---|---|
| 拍照识别 · 1 样食材 | **3.4 秒** | 白底单品图 |
| 拍照识别 · 3 样食材 | 2.6 ~ 3.5 秒 | 每样单独测的 |
| 拍照识别 · **40 样食材** | **51.5 秒** | 40 种食材拼图 |
| 菜谱生成 · 3 道菜 | **20.0 秒** | |

### 关键结论：识别耗时和「画面里有几样东西」成正比

模型是一个一个往下写的，写得越多越慢。粗略估算：

```
耗时 ≈ 3 秒 + 1.2 秒 × 食材数量
```

所以：

- 拍几样 → 3 秒左右，很流畅
- 拍十几样 → 20 秒左右
- **拍满一整箱（30+ 样）→ 40 秒以上**

### 对演示的影响（重要）

> ⚠️ **演示时别对着整台冰箱拍。** 打开冰箱门、拍**其中一层**（10 样以内），
> 识别 10 秒左右就出来了，节奏好看得多。
> 拍满一整箱要等 40 秒以上，台下会冷场。

菜谱生成 20 秒也偏长，所以界面上写了「约需 10~20 秒」。
彩排时把这个等待时间算进去，或者提前生成好。

### 超时配置（都够用，别乱调）

| 位置 | 值 | 说明 |
|---|---|---|
| 客户端读超时 | 120 秒 | `ApiClient.kt` |
| 后端 AI 超时 | 90 秒 | `AI_TIMEOUT_SECONDS` |

90 秒大约能撑 65 样食材。真超了也不会崩 ——
会降级成 MOCK 数据并附上「AI 调用失败」的说明。

## 二、识别效果

### 单品（白底图）

| 图片 | 结果 | 置信度 |
|---|---|---|
| broccoli.jpg | 西兰花 | 0.98 |
| apple.jpg | 苹果 | 0.99 |
| beef.jpg | 牛排 | 0.98 |

### 多品（40 种食材拼图）

**40 种一个不漏**，而且每样都给出了：

```json
{ "name": "西红柿", "quantity": 1, "unit": "个", "confidence": 0.95,
  "category": "蔬菜", "storage_location": "常温", "shelf_life_days": 7 }
```

- 分类（蔬菜 / 肉类 / 乳制品 / 海鲜…）**全对**
- 存放位置（冷藏 / 冷冻 / 常温）**全对** —— 肉类归冷冻、蔬菜归冷藏、土豆归常温
- 保质期天数合理（鸡蛋 30 天、牛奶 7 天、冷冻肉 90 天）
- 置信度大多 0.95；模糊的「海鲜」自动降到 0.8
- `needs_review = false`，没有误报需要人工复核

### 这条结论很重要

**AI 会自己推出 `category`、`storage_location`、`shelf_life_days`。**

也就是说：**食材库不需要穷举名称。** 遇到没见过的食材，
AI 照样能给名字、分类、存放位置和保质期 —— 唯一缺的是**图片**
（匹配不上会退化成「首字 + 色块」占位）。

所以「把食材库扩充到大众冰箱的规模」这件事，真实工作量是
**补图片**，不是补名称表。详见 `07-第二轮反馈修复.md` 之外的讨论。

## 三、菜谱生成

输入：鸡蛋 6 个、西红柿 3 个、青椒 2 个、豆腐 1 盒

输出（20 秒）：3 道菜，结构完整 ——
菜名、描述、耗时、难度、食材（含数量单位）、步骤、营养估算、缺料计算。

「番茄炒蛋」的食材返回 `available: true`，`missing_ingredients: []`，
说明**库存可用性是基于真实库存重算的**，没有采信模型自报。

## 四、复现方式

```bash
cd backend
.venv/Scripts/python.exe scripts/check_ai.py     # 三步检测：文本 / 视觉 / JSON
```

会依次测文本模型、视觉模型（用真实食材照片，不是占位图）、JSON 结构化输出。
