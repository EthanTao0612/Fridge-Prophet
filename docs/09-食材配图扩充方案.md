# 09 · 食材配图扩充方案

> **这份文档是一份「待执行」的操作手册。** 生成图片要花积分，所以现在不动手，
> 等积分充足时照这份一步步做即可。工作链已经全部验证过（项目现有的 40 张就是这么来的）。

---

## 一、为什么要扩

Ethan 的真机上反馈：「食材虽然能正确识别，但**没有配图**」。

实测他冰箱里 37 样食材：

| | 数量 | 举例 |
|---|---|---|
| 有图 | 25 样 | 鸡蛋、西红柿、鸡胸肉、西兰花… |
| **无图** | **12 样** | 黑胡椒、柠檬、猕猴桃、石榴、芦笋、青柠、蓝莓、覆盆子、菠萝、芒果、核桃、杏仁 |

**现有 40 张覆盖的是「基础蔬菜 + 主食」，水果 / 坚果 / 菌菇几乎空白。**

### 为什么没图就显示不出来

`ingredient_image_service.py` 的规则匹配不上 → `resolve_ingredient_image()` 返回 `None`
→ 客户端显示「首字 + 哈希色块」占位。

注意：**这是设计好的降级**，不是坏了。代码里明确写了不给通用兜底图 ——
一列里出现五张一样的图，用户会以为列表渲染坏了，比没图更糟。

### 这印证了之前那个判断

AI **能识别**「猕猴桃」，也能自己推出它的分类、存放位置、保质期。
缺的只是**图片**。

所以「把食材库扩到大众冰箱的规模」的真实工作量是 **补图片**，
不是补名称表、不是补分类。详见 `07` 里的相关讨论。

## 三、完整操作链

### 第 1 步：先把 key 加进规则表

编辑 `backend/app/services/ingredient_image_service.py` 的 `INGREDIENT_RULES`。

**规则表的顺序是语义的一部分**：从上往下匹配、命中即停。
先把 key 加上、图还没有也没关系 —— 消费侧会逐级降级，只返回磁盘上真实存在的图，
所以「代码先铺好、图后补」是安全的。

### 第 2 步：准备 Pillow 环境（不要污染项目 venv）

```bash
# 独立的工具环境
"<受管 python>" -m venv <隔离环境>
"<隔离环境>/Scripts/python.exe" -m pip install Pillow
```

### 第 3 步：**串行**生成图片

> ⚠️ **绝对不能并行。** 实测过：并行时 `output_dir` 参数会失效、
> 所有图写进同一个目录；而输出文件名只带**秒级**时间戳，
> 同一秒完成的多张图文件名相同 → **后写的覆盖先写的**。
> 真实案例：并行 11 个请求只活下来 8 个文件，3 张的积分白花。

一张一张来：生成 → 确认落盘 → 再发下一个。

**目录名就是 key**（不要靠顺序对应，顺序一错就会「麻婆豆腐配了番茄炒蛋的图」）：

```
.tmp-images-ingredients/
    lemon/            xxx.png    →  static/ingredients/lemon.jpg
    blueberry/        yyy.png    →  static/ingredients/blueberry.jpg
```

**所有 prompt 共用一个固定的风格后缀**，只换主体描述。风格词一个字都别动，
否则整批图看起来像拼凑的：

```python
STYLE = (
    " 45-degree overhead angle, soft diffused natural window light from the left, "
    "shallow depth of field, clean pure white background, single subject, "
    "high detail, commercial product photography style. "
    "No text, no watermark, no people, no hands, no plate, no bowl."
)
prompt = f"Professional food photography of a single fresh {ingredient} on a pure white background.{STYLE}"
```

> 项目对食材图有明确要求（Ethan 定的）：**真实食材照片 + 纯白底 + 单个主体 +
> 产品摄影质感**。不要程序绘制的插画 —— 他之前因为这个明确提过意见。
>
> 和菜谱图不同：食材图**不放盘子碗**，因为冰箱列表里是「生的食材」，
> 摆盘会显得像成品菜。

### 第 4 步：转格式并入库

```bash
python tools/import-images.py --kind ingredients --check   # 先检查缺什么
python tools/import-images.py --kind ingredients           # 真正转换
```

脚本会：PNG → JPEG（**长边 512、quality 86、progressive**）、RGBA→RGB、只缩不放。
食材图的长边 512 是按「冰箱列表 44dp 缩略图 × 3x 屏」算的，不用更大。

脚本用 **AST 解析规则表**（不 import，避免依赖问题），并会**报告还缺哪些 key**。

### 第 5 步：做拼图核对

生成完一定要核对「哪张图是哪个 key」。逐张看要读 N 次图片，很费上下文 ——
**做成一张带标签的拼图，只读一次**。标签写在图**下方**（不遮挡内容），
用纯 ASCII 的 key 当标签。

### 第 6 步：提交

- 转换后的 `backend/static/ingredients/*.jpg` **要提交**（随 Git 走）
- 原始 PNG 目录 `.tmp-images-ingredients/` **已在 .gitignore 里**，不要提交

## 四、必须注意的坑

### ① 规则顺序：单字关键词会互相抢

这是**已经踩过**的坑。真实案例：

- `鸡肉` 规则里有单字 `鸡`，而 `鸡蛋` 也含 `鸡` →
  「青椒炒鸡蛋」被配上了煎鸡腿的图。
  **解法**：蛋类规则排在鸡肉前面（`鸡蛋` 先被蛋类命中）。
- 这次要加的新 key 里有两个类似的：
  - **「猕猴桃」含「桃」** → 若加 `peach` 规则且用单字 `桃`，
    猕猴桃会被抢走。**解法**：`kiwi` 排在 `peach` 之前，或用 `桃子` 当关键词。
  - **「核桃」也含「桃」** → 同上，`walnut` 也要排在 `peach` 之前。
  - **「青柠」含「柠」** → 用全词 `柠檬` 当关键词就不会冲突，别用单字 `柠`。

**加新规则前先自问：这条的关键词会不会被上面某条先命中？**

### ② 并行 = 白花积分

见上面第 3 步。**串行，一张一张来。**

### ③ Pillow 的三个细节

```python
with Image.open(src) as im:
    if im.mode not in ("RGB", "L"):     # ① PNG 可能带 alpha，直接存 JPEG 会报错
        im = im.convert("RGB")
    if max(im.size) > MAX_EDGE:          # ② 只缩不放，放大只会变糊还变大
        im = im.resize(...)
    im.save(dst, format="JPEG", quality=86, optimize=True, progressive=True)  # ③
```

### ④ 不要给兜底图

食材图**故意没有**通用兜底图（`has_fallback: False`）。
匹配不上就返回 `None`，客户端显示占位样式。
一列里出现五张一样的通用图，用户会以为列表坏了。

## 五、验收

```bash
cd backend

# ① 规则表顺序的回归测试（图还没生成也能测）
.venv/Scripts/python.exe -m pytest tests/ -k ingredient

# ② 打真实 HTTP，确认新图能取到、且不存在的图确实 404
curl -s -o /dev/null -w "HTTP %{http_code}  type=%{content_type}\n" \
  http://127.0.0.1:8000/static/ingredients/lemon.jpg
# → HTTP 200  type=image/jpeg

curl -s -o /dev/null -w "HTTP %{http_code}\n" \
  http://127.0.0.1:8000/static/ingredients/nope.jpg
# → HTTP 404

# ③ 顺便确认有 etag / last-modified（客户端才能做磁盘缓存）
curl -sI http://127.0.0.1:8000/static/ingredients/lemon.jpg \
  | grep -iE "etag|last-modified|content-length"
```

最后在真机上打开冰箱页，确认新补的食材都有图了。
