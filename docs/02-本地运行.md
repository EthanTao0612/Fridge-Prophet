# 02 · 在本地把它跑起来

这一篇的目标：**电脑上能跑后端，手机上能装上 App，App 能连上电脑的后端。**

不需要任何云服务账号。`DASHSCOPE_API_KEY` 留空时后端会自动进入 MOCK 模式，  
返回内置的演示数据，整条业务链路照样能跑通——所以你可以先不管 AI 密钥。

---

## 一、先把后端跑起来

### 最快的做法：双击

在文件管理器里打开项目根目录（就是包含 `README.md`、`backend`、`android`、`tools`  
的那个文件夹），**双击 `start-backend.bat`**。

弹出的黑窗口里会自动完成：建虚拟环境 → 装依赖 → 复制配置 → 打印局域网 IP → 启动服务。  
重复双击是安全的，已经就绪的步骤会自动跳过。

> 为什么需要这个 `.bat`：真正的逻辑写在 `tools/start-backend.sh` 里，  
> 但 Windows 不能靠双击运行 `.sh` 文件，所以加了一层包装。  
> 这个 `.bat` 会自动寻找你机器上的 bash（优先用 WorkBuddy 内置的 PortableGit）。

<details>

<summary>用命令行执行（点击展开）</summary>

```bash
cd "G:/workbuddy/任务路径/Fridge-Prophet"    # 进入项目根目录
bash tools/start-backend.sh
```

和双击 `.bat` 效果完全一样。

</details>

<details>

<summary>手动分步执行（点击展开）</summary>

### 1. 装依赖（只需做一次）

```bash
cd "G:/workbuddy/任务路径/Fridge-Prophet/backend"

# 建一个独立的虚拟环境，不污染系统 Python
C:/Users/Atao/.workbuddy-ai/binaries/python/versions/3.13.12/python.exe -m venv .venv

# 装依赖
.venv/Scripts/python.exe -m pip install -r requirements.txt
```



> Windows 用 `.venv/Scripts/`，macOS / Linux 换成 `.venv/bin/`。

### 2. 生成配置文件

```bash
cp .env.example .env
```

`.env` 里**至少**要改一项：`SECRET_KEY`。它是签发登录令牌用的，上线前必须换成随机串。

```bash
.venv/Scripts/python.exe -c "import secrets;print(secrets.token_urlsafe(48))"
```

把输出粘到 `.env` 的 `SECRET_KEY=` 后面。其余项先留空。

**为什么可以留空：**

| 配置项                 | 留空时会发生什么                                     |
| ------------------- | -------------------------------------------- |
| `DASHSCOPE_API_KEY` | 自动进入 MOCK 模式，识别和菜谱都返回演示数据                    |
| `DATABASE_URL`      | 自动用 SQLite，文件生成在 `backend/fridge_prophet.db` |
| `SUPABASE_URL`      | 图片存本地磁盘，不传云端                                 |

### 3. 启动

```bash
.venv/Scripts/python.exe run.py
```

</details>

看到这两行就成功了：

```
  接口文档:  http://127.0.0.1:8000/docs
  健康检查:  http://127.0.0.1:8000/health
```

浏览器打开 <http://127.0.0.1:8000/docs>，能看到全部接口并且可以直接点着试。  
**这个页面是你调试时最有用的东西**，比看日志快得多。

> **注意：必须用 `.venv/Scripts/python.exe`，不能用系统的 `python`。**  
> 系统 Python 里没装这些依赖，会报 `ModuleNotFoundError: No module named 'uvicorn'`。

### 4. 自检两个外部依赖

```bash
.venv/Scripts/python.exe scripts/check_supabase.py   # 数据库通不通、11 张表在不在
.venv/Scripts/python.exe scripts/check_ai.py         # AI 密钥对不对
```

两个脚本都会把报错翻译成人话，比如密钥填错了会直接告诉你「这个 key 不是百炼的格式」。

### 5. 跑两套测试

```bash
# ① 进程内测试：直接调应用，不起网络栈，快
.venv/Scripts/python.exe tests/test_e2e.py
# 应该 251 项全过

# ② HTTP 冒烟测试：打真实运行中的服务，走网络栈
.venv/Scripts/python.exe scripts/smoke_http.py
# 应该 62 项全过
```

两套都要跑，它们测的不是一回事：

|        | `test_e2e.py`          | `smoke_http.py`          |
| ------ | ---------------------- | ------------------------ |
| 调用方式   | TestClient，直接调 ASGI 应用 | 真实 HTTP 请求               |
| 能发现    | 业务逻辑错误                 | 网络、端口、上传、反向代理、HTTPS 的问题  |
| 需要服务在跑 | 不需要                    | **需要**                   |
| 部署后能跑  | 不能                     | **能**（`--base-url` 指向线上） |

部署完服务器后，只有第二个能帮你发现 Nginx 配错、证书没生效这类问题：

```bash
.venv/Scripts/python.exe scripts/smoke_http.py --base-url https://你的域名
```

**改动后端之后先跑这两套**，比手动点一遍快得多。

## 二、把 App 装到手机上

### 先说清楚三件事

1. **App 和后端不在同一台机器上**，所以 App 不能写 `127.0.0.1`——那是手机自己。
2. 手机和电脑必须在**同一个 WiFi** 下。
3. 电脑的防火墙要放行 8000 端口，否则手机连不上。

> 第 3 条在**你这台电脑上已经确认过是通的**（WLAN 网络类别为「公用」，
> 而 `python.exe` 的入站放行规则正好覆盖公用网络）。不用额外操作。

### 0. 手机端先做准备（只做一次）

#### 第 1 步：打开「开发者选项」

这个菜单默认是隐藏的，要手动触发：

1. 打开手机「设置」→ 找到「关于手机」（有的叫「我的设备」「关于本机」）
2. 找到「**版本号**」
3. **连续点它 7 次**，屏幕会提示「您已处于开发者模式」或「还剩 N 步」

各家叫法不一样，对照着找：

| 品牌 | 「版本号」在哪儿 |
|---|---|
| 小米 / Redmi | 设置 → 我的设备 → 全部参数 → MIUI 版本 |
| 华为 / 荣耀 | 设置 → 关于手机 → 版本号 |
| OPPO / 一加 / realme | 设置 → 关于本机 → 版本信息 → 版本号 |
| vivo / iQOO | 设置 → 关于手机 → 软件版本号 |
| 三星 | 设置 → 关于手机 → 软件信息 → 编译编号 |

#### 第 2 步：打开「USB 调试」

回到「设置」→「系统」→「开发者选项」（有的藏在「更多设置」里）
→ 找到「**USB 调试**」→ 打开。

> ⚠️ **小米 / Redmi 用户注意**：还要额外打开「**USB 调试（安全设置）**」，
> 否则装 App 时会被拦下来。打开它可能要求登录小米账号并插入 SIM 卡。
>
> ⚠️ 华为用户注意：部分机型的「USB 调试」在「开发人员选项」里叫「USB 调试」，
> 但还需要把「仅充电模式下允许 ADB 调试」一并打开。

#### 第 3 步：用数据线连电脑

> ⚠️ **线必须是能传数据的线。** 很多线只供电不传数据（尤其是充电宝、小家电附带的线），
> 插上后电脑毫无反应，就是这个原因。换一根手机原装线最稳。

连上后手机会弹出「**是否允许 USB 调试？**」→ 勾选「始终允许」→ 点「**允许**」。

如果没弹窗：下拉手机通知栏，把 USB 用途从「仅充电」改成「**传输文件 / MTP**」，
弹窗通常就出来了。

#### 第 4 步：在电脑上确认手机被认出来了

```bash
"G:/Android/Sdk/platform-tools/adb.exe" devices
```

正确的结果长这样（`device` 前面那串是手机序列号）：

```
List of devices attached
ABCD1234EFGH    device
```

三种状态的含义：

| 显示 | 含义 | 怎么办 |
|---|---|---|
| `device` | 正常，可以继续 | — |
| `unauthorized` | 手机上的授权弹窗没点 | 看手机屏幕，点「允许」；没弹窗就拔了重插 |
| 只有 `List of devices attached` 一行 | 线或驱动的问题 | 换线、换 USB 口（台式机优先插机箱**后面**的口） |

**看到 `device` 才能往下走。**

### 1. 查出电脑的局域网 IP

```bash
ipconfig | grep -A 5 "无线局域网适配器 WLAN" | grep "IPv4"
```

或者直接看全部：

```bash
ipconfig
```

找到形如 `192.168.3.5` 的那个地址。

> **你这台电脑当前的局域网 IP 就是 `192.168.3.5`**，所以下面命令里的地址直接复制即可。
>
> 不过要记住：**这个 IP 是路由器分配的，可能变。** 换网络、路由器重启之后都可能不同。
> 每次双击 `start-backend.bat` 时，它都会把当前的局域网地址打印在窗口里——
> **以它打印的为准**，不要一直用记忆里的旧值。IP 变了而 App 还用旧地址，表现就是「连不上后端」。

### 2. 指定后端地址（不用改代码）

地址是**构建时注入**的，不需要（也不应该）去改 `build.gradle.kts`。

```bash
cd "G:/workbuddy/任务路径/Fridge-Prophet/android"
export JAVA_HOME="G:\Android\jdk-17.0.20.1+1"

# 模拟器：默认值 10.0.2.2 就是模拟器眼中的宿主机，不用传参数
"G:/Android/gradle-8.14.5/bin/gradle.bat" installDebug

# 真机：传你的局域网 IP
"G:/Android/gradle-8.14.5/bin/gradle.bat" installDebug \
  -PAPI_BASE_URL=http://192.168.3.5:8000/
```

三种注入方式，优先级从高到低：

| 方式    | 写法                               | 场景      |
| ----- | -------------------------------- | ------- |
| 命令行参数 | `-PAPI_BASE_URL=http://...`      | 临时切换，推荐 |
| 环境变量  | `export API_BASE_URL=http://...` | CI 流水线  |
| 配置文件  | 写进 `android/gradle.properties`   | 本地长期固定  |

结尾的 `/` 可有可无，构建脚本会自动补上。

> **为什么不做成硬编码**：写死在代码里，一旦提交进 Git，别人 clone 下来就指向了你的服务器；  
> 而且 GitHub Actions 无法在不改代码的前提下打出指向正式服务器的包。

### 3. 构建并安装

```bash
# installDebug 会直接装到已连接的设备，不用手动 adb install
"G:/Android/gradle-8.14.5/bin/gradle.bat" installDebug \
  -PAPI_BASE_URL=http://192.168.3.5:8000/
```

如果只想出包不安装：

```bash
"G:/Android/gradle-8.14.5/bin/gradle.bat" assembleDebug
```

产物在：

```
android/app/build/outputs/apk/debug/app-debug.apk
```

手动安装的话：

```bash
"G:/Android/Sdk/platform-tools/adb.exe" devices          # 确认能看到设备
"G:/Android/Sdk/platform-tools/adb.exe" install -r \
  app/build/outputs/apk/debug/app-debug.apk
```

手机需要先打开「开发者选项 → USB 调试」。

> 没装 Android Studio 也完全没问题，上面这套命令行工具链已经装好了。  
> 当然，如果你想要代码补全和断点调试，装一个 Android Studio 会舒服很多——  
> 用它的「Open」直接打开 `android/` 目录即可，它会自动识别 Gradle 工程。

装好 App 后，按这个顺序点一遍，每一步都应该成功：

| 步骤 | 操作                | 期望结果                    |
| -- | ----------------- | ----------------------- |
| 1  | 注册一个账号            | 直接进入 5 步引导问卷            |
| 2  | 填完问卷              | 进入首页                    |
| 3  | 点「扫描我的冰箱」         | 相机打开                    |

## 四、常见问题

**手机连不上后端**

按顺序排查：

1. 手机浏览器打开 `http://电脑IP:8000/health`，看能不能出内容。出不来就是网络问题。
2. 后端必须监听 `0.0.0.0` 而不是 `127.0.0.1`——`run.py` 里已经设好了。
3. Windows 防火墙：控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙 → 勾上 Python。
4. 手机是不是连了 5G 频段而电脑连了 2.4G？有些路由器会隔离这两个网段。

**构建报 `Failed to find target with hash string 'android-36'`**

Android SDK 的 platform 没装好。检查 `G:/Android/Sdk/platforms/android-36/source.properties` 是否存在。

**构建报 `Unsupported class file major version`**

Gradle 用错了 JDK。确认 `JAVA_HOME` 指向 JDK 17：

```bash
export JAVA_HOME="G:\Android\jdk-17.0.20.1+1"
"G:/Android/jdk-17.0.20.1+1/bin/java.exe" -version
```

**首次构建特别慢**

正常。要下载 AGP、Kotlin 编译器、Compose、Hilt 等一堆东西，几百 MB。  
已经配了阿里云镜像加速，第二次构建会快很多。

**改了代码后 App 没变化**

`assembleDebug` 之后要重新 `adb install -r`。加 `-r` 是覆盖安装，不会丢数据。

**改了代码但行为没变**

先确认没有**旧的服务器进程还在占着 8000 端口**。这个坑很隐蔽：

Windows 允许 `0.0.0.0:8000` 和 `127.0.0.1:8000` 同时存在。  
如果你之前启动过一个服务没关掉，新启动的那个会绑到 `0.0.0.0`，  
但你用浏览器访问 `127.0.0.1` 时，Windows 会优先命中**更具体的** `127.0.0.1` 那个 ——  
也就是**旧进程**。表现出来就是「代码明明改了，行为一点没变」。

排查：

```bash
netstat -ano | grep ":8000.*LISTENING"
```

如果输出了不止一行，或者 PID 不是你现在这个进程，就把它杀掉：

```powershell
Stop-Process -Id <上面看到的PID> -Force
```

**App 里食材名显示成空白**

后端返回的字段名是 `food_name` 而不是 `name`（只有 AI 识别结果用 `name`）。  
如果新增了读取库存/采购项的代码，记得用 `food_name`。  
App 的 DTO 里已经用 `@SerialName("food_name")` 映射好了，照抄现有的写法即可。

**菜谱说某样食材「有」，采购清单却让你去买**

这是单位换算的边界情况。比如冰箱里记的是「豆腐 1 盒」，菜谱需要「豆腐 300 g」——  
盒和克之间没有换算关系，算不出到底够不够。

后端对这种情况的处理是：**按「大概率有」处理，不列进采购清单**。  
理由很简单——让用户去买冰箱里已经有的东西，比漏买一样更糟。

这个判断在 `recipe_service._recompute_availability` 和  
`shopping_service.compute_missing` 两处必须保持一致，否则界面会自相矛盾。  
如果你要改其中一处的逻辑，记得另一处也要改。
