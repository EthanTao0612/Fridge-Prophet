# 03 · 部署到公网

> 这份文档在**阶段三**执行。现在先看不做也行，提前知道要准备什么。
> 里面出现的 `你的服务器IP`、`你的域名` 等占位符，到时候替换成真实值。

---

## 一、先想清楚三件事

### 1. 服务器买哪里

**中国香港节点**。原因只有一个：免备案。

大陆节点必须走 ICP 备案，流程要 1～3 周，比赛来不及。香港节点访问速度也够用，
国内延迟大约 30～60ms，对拍照识别这种场景完全无感。

### 2. 域名要不要买

**要买。** 这不是可选项，原因是 Android 的限制：

> Android 9（API 28）起，系统默认**禁止 App 使用明文 HTTP**。
> 我们的 App `minSdk = 26`，`targetSdk = 36`，所以正式包必须走 HTTPS。

HTTPS 需要证书，证书需要域名。一个 `.top` 或 `.xyz` 域名一年十几块钱，
是整条链路里最便宜也最不能省的一环。

> 我们已经在工程里配好了两套网络安全策略：
> `main` 只允许 HTTPS，`debug` 允许明文。
> 所以**调试阶段不受影响**，只有出正式包时才必须有 HTTPS。

### 3. 数据库装在哪

**不装在服务器上。** 用 Supabase 托管：

- 免运维、自带备份
- 免费额度 500MB 数据库 + 1GB 图片存储，比赛够用
- 服务器挂了数据还在

代价是多了几十毫秒网络往返，可以接受。

## 二、买服务器

腾讯云 → 轻量应用服务器：

| 项 | 选择 |
|---|---|
| 地域 | **中国香港** |
| 镜像 | Ubuntu 22.04 LTS |
| 套餐 | 2 核 2G / 3M 带宽（最低配也够） |
| 时长 | 买 1 个月先跑通，演示前再续 |

买完在控制台的**防火墙**里放行这几个端口：

- `22`（SSH，默认已开）
- `80`（HTTP，用于申请证书）
- `443`（HTTPS）

## 三、服务器初始化

```bash
ssh root@你的服务器IP
```

### 1. 建专用用户

不要用 root 跑服务，这是基本安全习惯。

```bash
adduser fridge
usermod -aG sudo fridge
```

### 2. 基础环境

```bash
apt update && apt upgrade -y
apt install -y python3.11 python3.11-venv python3-pip nginx git curl

# 时区改成国内，否则日志时间看不懂
timedatectl set-timezone Asia/Shanghai
```

### 3. 上传代码

**方式 A：从 GitHub 拉（推荐）**

先在本地把项目推到 GitHub，然后在服务器上：

```bash
su - fridge
git clone https://github.com/你的用户名/Fridge-Prophet.git ~/app
```

**方式 B：直接传（代码还没上 GitHub 时用）**

在本地执行：

```bash
scp -r "G:/workbuddy/任务路径/Fridge-Prophet" fridge@你的服务器IP:~/app
```

> 注意 `.env` 会被 `.gitignore` 排除，所以**方式 A 拉下来的代码里没有 `.env`**，
> 需要按下一步手动创建。这是故意的——密钥不该进版本库。

## 四、配置并启动后端

```bash
cd ~/app/backend

# 建虚拟环境
python3.11 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
```

### 生成 `.env`

```bash
cp .env.example .env
nano .env
```

必须填的四项：

```ini
DEBUG=false

# 1. 数据库：从 Supabase 控制台复制
#    Project Settings → Database → Connection string → URI
#    把 postgresql:// 改成 postgresql+psycopg://
#    结尾补上 ?sslmode=require（见下面那条警告）
DATABASE_URL=postgresql+psycopg://postgres.abcdefgh:密码@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres?sslmode=require

#    ⚠️ ?sslmode=require 别省。Supabase 强制 SSL，而 psycopg 默认是
#       prefer（先试 SSL，失败就退回明文）—— 退回明文会被 Supabase 拒掉，
#       而且报错很不直观，表现出来是「有时候连得上、有时候连不上」。
#       显式写上，连不上就干脆连不上，不会出现半通不通的状态。

# 2. 令牌密钥：一定要重新生成，不要用开发时那个
#    本地执行 python -c "import secrets;print(secrets.token_urlsafe(48))"
SECRET_KEY=这里填一长串随机字符

# 3. AI 密钥
DASHSCOPE_API_KEY=sk-你的百炼key

# 4. 图片存储
SUPABASE_URL=https://abcdefgh.supabase.co
SUPABASE_SERVICE_KEY=你的service_role_key
```

> **`SUPABASE_SERVICE_KEY` 绝对不能写进 App**。它是最高权限的密钥，
> 只能待在服务器上。App 只跟我们的后端说话，不直接碰 Supabase。

### 先手动跑一次，确认没问题

**⚠️ 顺序很重要：先在默认 SQLite 上跑测试，再切 Supabase。**

```bash
# ① 先不要填 DATABASE_URL（用默认的 SQLite）跑一遍完整测试，
#    确认代码在这台服务器上没问题。这一步完全不碰 Supabase。
.venv/bin/python tests/test_e2e.py     # 251 项

# ② 再把 Supabase 的连接串填进 .env，启动
.venv/bin/python run.py                # 看到监听 0.0.0.0:8000 就对了
```

**为什么不直接连 Supabase 跑测试**：那 251 项测试会**注册几十个测试账号、
往库里灌食材和菜谱**。跑完你的生产库里就多出一堆垃圾数据，
清理起来还得按邮箱前缀一条条删。

切到 Supabase 之后，先跑一遍 Supabase 自检：

```bash
.venv/bin/python scripts/check_supabase.py
```

它会依次检查三件事，**都要是 `[OK]`**：

1. 数据库能不能连上（连接串、密码、SSL 对不对）
2. 11 张表建好了没
3. **Storage bucket 能不能访问 —— 这一项最关键**

> **如果本机连不上 Supabase Storage**（国内网络会按 SNI 拦截 `*.supabase.co`，
> 表现为 TLS 握手被重置，而 `api.supabase.com` 和数据库端口都正常），
> 有两条路建 bucket：
>
> ① **在 Dashboard 手动建** —— Storage → New bucket → 名字 `fridge-photos`、勾 Public。
>
> ② **直接往数据库里插一行** —— bucket 的元数据就存在 `storage.buckets` 表里，
> 有数据库权限就能插（和 Storage API 内部做的事一样）：
>
> ```sql
> insert into storage.buckets (id, name, public) values ('fridge-photos', 'fridge-photos', true);
> ```
>
> 插完可以用管理 API 独立确认（`GET /v1/projects/{ref}/storage/buckets`），
> 不用依赖被阻断的那个域名。
>
> ⚠️ 这是**绕行**不是常规做法。能走 Storage API 时就走 API。
>
> ⚠️ **第 3 项千万别跳过。**
> 图片默认存 Supabase Storage，但 **bucket 是要先建出来的**，
> 而这个脚本是建 bucket 的唯一入口。
>
> 没跑的话，第一次上传会因为 bucket 不存在而失败，然后**静默退回本地磁盘** ——
> 图片照样能显示，你根本看不出来，但「照片不怕服务器重装」这个好处已经没了，
> 而且要到服务器真出事那天才会发现。
>
> （后端启动时也会再检查一次并打日志，看到
> `图片存储: ⚠️ 本地磁盘 —— Supabase bucket 不可用，已退回` 就是出问题了。
> 正常应该显示 `图片存储: Supabase Storage（bucket=fridge-photos）`。）

然后验证只做**只读**的：

```bash
curl http://127.0.0.1:8000/health      # 应返回 {"status":"healthy",...}
```

想验全链路，等 Nginx 配好后在**手机上装 App 走一遍** ——
那才是真实场景，而且产生的数据是你自己的，不是测试垃圾。

确认没问题后 `Ctrl+C` 停掉，接下来交给 systemd 管。

## 五、systemd 守护

让它开机自启、崩了自动重启。

```bash
sudo nano /etc/systemd/system/fridge.service
```

写入：

```ini
[Unit]
Description=Fridge Prophet Backend
After=network.target

[Service]
Type=simple
User=fridge
WorkingDirectory=/home/fridge/app/backend
Environment="PATH=/home/fridge/app/backend/.venv/bin"
ExecStart=/home/fridge/app/backend/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 2
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

注意两点：

- `--host 127.0.0.1` —— 只监听本机，外部流量一律走 Nginx。**不要写成 0.0.0.0**。
- `--workers 2` —— 2 核机器开 2 个进程。

启用：

```bash
sudo systemctl daemon-reload
sudo systemctl enable fridge
sudo systemctl start fridge

# 看状态
sudo systemctl status fridge
sudo journalctl -u fridge -f      # 实时看日志
```

## 六、Nginx 反代

```bash
sudo nano /etc/nginx/sites-available/fridge
```

写入：

```nginx
server {
    listen 80;
    server_name 你的域名.com;

    # 照片上传可能有 10MB，这个要放开，默认 1M 会 413
    client_max_body_size 20M;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # AI 识别一张图可能跑几十秒，超时给够
        proxy_read_timeout 180s;
        proxy_send_timeout 180s;
    }
}
```

启用：

```bash
sudo ln -s /etc/nginx/sites-available/fridge /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default     # 删掉默认站点
sudo nginx -t                                    # 检查语法
sudo systemctl reload nginx
```

### 把域名解析过来

在域名服务商那里加一条 A 记录：

```
类型: A
主机记录: @  （或者 api，看你想用哪个子域名）
记录值: 你的服务器IP
```

等几分钟生效，然后验证：

```bash
curl http://你的域名.com/health
```

## 八、把 App 指向公网地址

地址是**构建时注入**的，不用改代码：

```bash
cd "G:/workbuddy/任务路径/Fridge-Prophet/android"
export JAVA_HOME="G:\Android\jdk-17.0.20.1+1"

"G:/Android/gradle-8.14.5/bin/gradle.bat" assembleRelease \
  -PAPI_BASE_URL=https://你的域名.com/ \
  --console=plain
```

结尾的 `/` 可有可无，构建脚本会自动补上。

> 如果你什么都不传就打了 release 包，构建日志会打印一条 `[WARN]` 提醒你
> 包内用的是占位地址 `https://api.example.com/`。看到这个警告说明包不能用。

打完后装到手机上，走一遍
[02 篇的九步验证清单](02-本地运行.md#三验证整条链路)——这次数据是真的存在云端了。

### ⚠️ 打完包必须验签，别直接装

**没有 `keystore.properties` 时 Gradle 会静默退回 debug 签名** ——
不报错、不警告，包照样能装能用，但**它签的不是你的密钥**。
后果是以后发新版本时，装了旧包的手机装不上
（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`），而且应用商店会拒收。

```bash
# 在 Git Bash 里跑（Windows 下 .bat 不能直接调，用 Python 转一手）
cd "G:/workbuddy/任务路径/Fridge-Prophet"
backend/.venv/Scripts/python.exe -c "
import subprocess, os
env = dict(os.environ, JAVA_HOME=r'G:/Android/jdk-17.0.20.1+1')
apk = r'G:\workbuddy\任务路径\Fridge-Prophet\android\app\build\outputs\apk\release\app-release.apk'
r = subprocess.run(['cmd','/c', r'G:\Android\Sdk\build-tools\36.0.0\apksigner.bat',
                    'verify','--print-certs', apk],
                   capture_output=True, encoding='utf-8', errors='replace',
                   stdin=subprocess.DEVNULL, timeout=180, env=env)
print((r.stdout or '') + (r.stderr or ''))
"
```

**看输出的 `DN` 那一行**：

| 输出 | 含义 |
|---|---|
| `CN=FridgeProphet, OU=Mobile, ...` | ✅ 对，是你自己的密钥 |
| `CN=Android Debug, O=Android, C=US` | ❌ **签错了**，包不能用，去检查 `android/keystore.properties` |

顺便确认地址也注入对了（包内不该再出现 `api.example.com`）：

```bash
backend/.venv/Scripts/python.exe -c "
import zipfile, re
apk = r'G:\workbuddy\任务路径\Fridge-Prophet\android\app\build\outputs\apk\release\app-release.apk'
z = zipfile.ZipFile(apk)
hits = set()
for n in z.namelist():
    if n.endswith('.dex'):
        for m in re.finditer(rb'https?://[A-Za-z0-9._\-/:]{6,60}', z.read(n)):
            s = m.group().decode('ascii','ignore')
            if 'example.com' in s or '你的域名' in s or 'placeholder' in s:
                hits.add(s)
print('包内占位地址:', sorted(hits) or '（无，说明注入正确）')
"
```

> 这两项**本机已经验证过一次**（2026-10-02）：release 包能构建、
> 签名是 `CN=FridgeProphet`、`-PAPI_BASE_URL` 注入生效。
> 所以这一步是确认「换成本地地址后依然正确」，不是从零摸索。

**另外强烈建议先在服务器上跑一遍冒烟测试**，确认线上环境没问题再打 App 包：

```bash
# 在服务器上执行（或在本地用 --base-url 指向线上）
cd ~/fridge-prophet/backend
.venv/bin/python scripts/smoke_http.py --base-url https://你的域名.com
```

这一步能发现本地测不出来的问题：Nginx 反代配错、HTTPS 证书没生效、
上传文件大小限制、CORS 配置。**打 App 包之前先过这一关**，
否则你可能要反复重打包装机才能定位问题。

## 九、Supabase 保活（重要，别跳过）

> **这是整个部署里最容易踩的坑。**

Supabase 免费版有个规则：**项目连续 7 天没有任何请求会被自动暂停**。
暂停后不是数据丢了，但需要手动去控制台点恢复，恢复要几分钟。
如果评委在你演示前一天点开，而项目是暂停状态——那就是灾难。

解决办法是在服务器上挂个定时任务，每天访问一次：

```bash
crontab -e
```

加一行：

```cron
# 每天 3:17 访问一次 Supabase，防止免费项目被判定为闲置
17 3 * * * curl -s -o /dev/null "https://你的项目ID.supabase.co/rest/v1/" -H "apikey: 你的anon_key"
```

> 时间故意选在 3:17 而不是 3:00，是为了避开整点——整点是各种定时任务的高峰，
> 错开一点更稳。

验证它生效：

```bash
# 手动跑一次，然后去 Supabase 控制台看项目的 Last Activity 有没有更新
curl -s -o /dev/null -w "%{http_code}\n" "https://你的项目ID.supabase.co/rest/v1/" -H "apikey: 你的anon_key"
```

## 九之二、给 AI 额度上一道保险

后端的接口**没有任何限流**，而注册是开放的 —— 理论上任何人发现你的域名后，
注册个账号就能反复调 `/vision/scan` 和 `/recipes/generate`，
**每一次都是在花你的百炼额度**。

比赛演示期间域名不公开，风险不大。但有个**不用改代码**的保险：

> 去百炼控制台设一个**消费限额**（费用中心 → 额度/预算管理）。
> 设成你充值的额度就行 —— 就算真被人刷，最多花完这些，不会继续扣。

顺便在 Nginx 那一层也可以简单挡一下（可选，不是必须）：

```nginx
# 同一 IP 每分钟最多 30 次请求，超了返回 429
limit_req_zone $binary_remote_addr zone=api:10m rate=30r/m;

server {
    ...
    location /api/ {
        limit_req zone=api burst=10 nodelay;
        ...
    }
}
```

演示前如果时间紧，**只做百炼限额那一步就够了** —— 那是兜底，Nginx 限流是锦上添花。

## 十、上线检查清单

部署完挨个确认一遍：

- [ ] `curl https://你的域名.com/health` 返回正常
- [ ] `sudo systemctl status fridge` 是 `active (running)`
- [ ] `sudo reboot` 重启服务器后，后端能自动起来（验证开机自启）
- [ ] **启动日志显示 `图片存储: Supabase Storage`**（不是「本地磁盘」）
- [ ] **`https://你的域名.com/docs` 打不开（404）** —— 确认 `DEBUG=false` 真的生效了
- [ ] App 正式包装在真机上，能完成九步全流程
- [ ] Supabase 保活定时任务已配好，手动跑过一次
- [ ] `.env` 里的 `SECRET_KEY` 是重新生成的，不是开发时那个
- [ ] 服务器上的代码里**没有** `.env`、`keystore.properties`、`*.jks`

> 怎么看启动日志：
>
> ```bash
> sudo journalctl -u fridge -n 30 --no-pager
> ```
>
> 正常应该看到这三行：
>
> ```
> 数据库已就绪: ...@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres
> 图片存储: Supabase Storage（bucket=fridge-photos）
> AI 状态: 已接入 qwen-vl-max / qwen-plus
> ```
>
> 第一行能看到 Supabase 域名 = 连上的是生产库，不是 SQLite；
> 第二行是 `Supabase Storage` 而不是「本地磁盘」= bucket 建好了。

### 上线后关掉接口文档

`/docs` 页面会暴露全部接口结构，正式环境建议关掉。在 `.env` 里加：

```ini
DEBUG=false
```

然后重启服务：

```bash
sudo systemctl restart fridge
```
