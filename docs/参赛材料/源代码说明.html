二、团队原创部分

以下全部为本团队从零编写，不含第三方代码：

2.1 后端服务（backend/app/）

模块文件原创内容
接口层api/v1/*.py全部 60+ 个 REST 接口的定义、参数校验、权限判定
业务层services/*.py食材匹配五级降级算法、菜谱推荐、缺料计算、采购清单生成、做菜扣减、家庭组可见范围、AI 配额、邮箱验证码、新鲜度计算
数据模型models/*.py22 张表的 SQLAlchemy 2.0 模型与关系设计
内容库data/food_tips.py89 条食品安全小贴士（含权威来源标注）
配置与依赖core/*.py、deps.py配置加载、JWT 鉴权、数据库会话管理、统一依赖注入

其中最具技术含量的原创算法：

  • 食材匹配五级降级（ingredient_image_service.py）

挡刀区规则 → 词库精确 → 别名 → 词库子串（最长优先）→ 关键词兜底。

让「肥羊肉」「内蒙古羔羊肉」这类词库没有的写法也能正确配图。

  • 菜谱读/写可见范围分离（recipe_service.py）

readable_recipe_clause / editable_recipe_clause —— 系统内置菜谱

所有用户共用一条记录，必须禁止用户删除或改写。

  • AI 每日配额双闸（quota_service.py）

按用户限流 + 全站限流，给账单兜底。

2.2 Android 客户端（android/app/src/main/java/）

模块原创内容
界面层全部 Compose 页面（首页 / 冰箱 / 菜谱 / 采购 / 广场 / 我的 / 扫描 / 登录 / 引导 / 家庭 / 小贴士），共 30+ 个 Composable
状态层全部 ViewModel 的业务逻辑（乐观更新、防抖、并发请求编排）
数据层Retrofit 接口定义、DTO、仓库封装、DataStore 本地存储
组件层ui/components/ —— 图片加载（自研 OkHttp + BitmapFactory，未引入图片库）、图片压缩与 EXIF 转正、空状态、卡片、动作按钮等
主题ui/theme/ —— 配色、字体、形状体系

其中值得一提的原创实现：

  • 图片上传前压缩 + EXIF 转正（PickedImage.kt）

实测把 4096×3072 / 2.0MB 压到 1200×1600 / 163KB（省 92%），

并手动读取 android.media.ExifInterface 修正旋转（重编码会丢 EXIF）。

  • 自研图片加载（RemoteImage.kt）

没有引入 Coil 等图片库 —— 本项目依赖矩阵较脆（曾因引入 Coil 3

触发 Gradle 依赖图序列化异常），改用 OkHttp + BitmapFactory + 内存缓存。

  • 乐观更新 + 防抖 350ms（ProfileViewModel.kt 等）

开关类设置不等服务器回包，失败才回滚。
