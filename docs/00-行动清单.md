## A 线：本地验证（不需要任何账号）

这条线的目的是**在花一分钱之前，先确认整个产品是通的**。

### A1. 跑后端 ✅ 已完成

后端在零配置下就能启动，这是刻意设计的：

- `DATABASE_URL` 留空 → 自动用 SQLite，文件在 `backend/fridge_prophet.db`
- `DASHSCOPE_API_KEY` 留空 → AI 自动进 **MOCK 模式**，返回演示数据

MOCK 模式的意义：你不用先花时间开通百炼、调通 API，就能把「扫描 → 识别 → 生成菜谱 → 采购」整条链路走完。等 MOCK 跑通了，再换真密钥，此时如果出问题，你明确知道是 AI 的问题，不是链路的问题。

**一条命令搞定**（在项目根目录执行）：

```bash
bash tools/start-backend.sh
```

脚本会自动建虚拟环境、装依赖、复制配置、打印局域网 IP。

> **更省事的做法：双击项目根目录下的 `start-backend.bat`。**
> 它做的事和上面完全一样，但不需要你打开终端、也不需要知道什么叫「cd 到项目根目录」。
> Windows 不能直接双击运行 `.sh` 文件，所以做了这个 `.bat` 包装。

<details>
<summary>手动分步执行（点击展开）</summary>

```bash
cd "G:/workbuddy/任务路径/Fridge-Prophet/backend"

# 建虚拟环境
C:/Users/Atao/.workbuddy-ai/binaries/python/versions/3.13.12/python.exe -m venv .venv

# 装依赖
.venv/Scripts/python.exe -m pip install -r requirements.txt

# 复制配置模板（先不用改任何东西）
cp .env.example .env

# 跑测试，确认 251 项全过
.venv/Scripts/python.exe tests/test_e2e.py

# 启动服务
.venv/Scripts/python.exe run.py
```

</details>

看到 `Uvicorn running on http://0.0.0.0:8000` 就成了。

> **最常见的错误**：直接敲 `python run.py`。
> 系统 Python 里没装这些依赖，会报 `ModuleNotFoundError: No module named 'uvicorn'`。
> 必须用虚拟环境里的解释器 `.venv/Scripts/python.exe`。

打开这个地址：http://127.0.0.1:8000/docs 就能看到自动生成的 API 文档，这个页面本身就可以当演示材料用。

**建议顺手做完 A1.5：在网页上把整条链路点一遍。** 不用装 Android、不用连真机，
五分钟就能验证后端到底对不对 —— 比 A2 快得多，出问题时也更容易判断是前端还是后端。

> 详细说明见 [02 · 本地运行](./02-本地运行.md)
> 网页上跑通全链路的七步操作见 [05 · 用接口文档跑通全链路](./05-用接口文档跑通全链路.md)

### A2. 真机跑通九步链路 ✅ 已完成（含 5 条反馈的真机验收）

这一步是**整个项目最重要的验证**。九步走通 = 产品成立；走不通 = 现在改还来得及。

**先查电脑局域网 IP**：

```bash
ipconfig | grep -A 6 "WLAN" | grep "IPv4"
```

记下形如 `192.168.1.23` 的地址。

**打 debug 包并装到手机**（手机和电脑连同一个 WiFi）：

```bash
cd "G:/workbuddy/任务路径/Fridge-Prophet/android"
export JAVA_HOME="G:\Android\jdk-17.0.20.1+1"

"G:/Android/gradle-8.14.5/bin/gradle.bat" installDebug \
  -PAPI_BASE_URL=http://192.168.1.23:8000/ \
  --console=plain
```

**按这个顺序点一遍，每步确认结果**：

| # | 操作 | 应该看到什么 | 不对的话查哪 |
|---|---|---|---|
| 1 | 打开 App | 不闪退，进入欢迎页 | 后端地址填错了 |
| 2 | 注册账号 | 进入问卷页 | 后端有没有在跑 |
| 3 | 填问卷（口味、忌口、健康） | 进入首页 | — |
| 4 | 点「扫描冰箱」，拍一张冰箱照片 | 出现识别中的进度 | 相机权限有没有给 |
| 5 | 确认识别结果，改几个数量 | 食材入库，首页显示库存 | MOCK 模式返回的是演示数据 |
| 6 | 点「推荐菜谱」 | 出现菜谱列表 | — |
| 7 | 点进某个菜谱 | 看到缺什么 / 怎么做 / 营养三段 | — |
| 8 | 从菜谱生成采购清单 | 清单里是**缺的**食材，不是全部 | 差集是后端算的，不该前端算 |
| 9 | 勾选买到的，点写回库存 | 首页库存数量更新 | — |

**第 5 步和第 8 步是重点**，它们验证了两条架构铁律：

- 第 5 步验证「**识别结果必须用户确认才入库**」——AI 猜错了你有机会改
- 第 8 步验证「**采购计算不用 AI**」——差集是确定性的算术，不该让 AI 算（AI 会算错数）

如果这两步行为不对，说明架构被破坏了，要立刻回头查，别往下走。

### A3. 生成签名密钥 ✅ **已经做过了，别重做！**

> ⚠️ **`android/release.jks` 已经生成好了，而且验证过能用
>（`apksigner` 查出来证书是 `CN=FridgeProphet`，不是 debug 签名）。**
>
> **不要重复运行下面这个脚本。** 重新生成会得到一把**不同的**密钥，
> 签名随之改变 —— 装了旧包的手机装不上新包
>（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`），应用商店也会拒绝更新。
> **密钥一辈子只能生成一次。**
>
> 这一节留着，是给「万一密钥丢了、必须推倒重来」的情况看的。

```bash
# ⚠️ 只在确定要换新密钥时才运行（正常情况不要跑）
cd "G:/workbuddy/任务路径/Fridge-Prophet"
bash tools/new-keystore.sh
```

脚本会问你别名和密码，然后自动生成 `android/release.jks` 和 `android/keystore.properties`。

**备份到 U 盘或密码管理器。** 密钥丢了，已发布的 App 就永远无法更新了。

> 详细说明见 [04 · 打包签名 APK](./04-打包APK.md)

## B 线：云账号（需要注册，有些要等审核）

**建议 A1 跑通后立刻开始 B 线**，因为账号审核和服务器开通有等待时间，可以跟 A 线的调试并行。

### B1. 开三个账号 **[你做]** ⏱ 40 分钟（不含等待）

| 账号 | 用途 | 费用 | 要拿什么 | 详细步骤 |
|---|---|---|---|---|
| **Supabase** | 云数据库（PostgreSQL） | 免费 | `DATABASE_URL` | [01 · 账号注册](./01-账号注册.md) |
| **阿里云百炼** | 通义千问 AI（识别 + 生成） | 有免费额度 | `DASHSCOPE_API_KEY` | [01 · 账号注册](./01-账号注册.md) |
| **腾讯云** | 服务器（跑后端） | 约 30-50 元/月 | 服务器 IP + root 密码 | [01 · 账号注册](./01-账号注册.md) |

**三个注意点**：

1. **腾讯云买「中国香港」节点**，不要买内地的。内地服务器对外提供 Web 服务需要 ICP 备案，备案要 7-20 个工作日，比赛等不起。香港节点免备案，但延迟略高（约 30-60ms），对演示完全够用。

2. **Supabase 免费版闲置 7 天会暂停项目**。这是演示前最致命的坑——你辛苦部署好，放一周没动，演示当天打开发现数据库连不上。`docs/03` 里给了保活 cron 的配置方法，**部署完就配上**。

3. **百炼的 Base URL 分地域**。通用地址 `https://dashscope.aliyuncs.com/compatible-mode/v1` 如果调不通，换成业务空间专属地址：`https://{你的业务空间ID}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`。这个坑不少人踩过。

### B2. 换真密钥再验一次 **[你做]** ⏱ 15 分钟

拿到 `DASHSCOPE_API_KEY` 后，填进 `backend/.env`，重启后端，**重新走一遍 A2 的九步链路**。

这一步很重要：MOCK 数据是写死的完美数据，真实 AI 会给你惊喜——比如把鸡蛋识别成鸭蛋、把数量认错。**现在发现比现场发现好。**

同时注意：
- 识别一张冰箱照片大概要 5-15 秒，App 的加载态要能撑住
- 百炼免费额度有限，别拿几十张照片猛刷
- 如果识别质量差，调整 prompt 里的引导词，或者换 `qwen-vl-max` 之外的模型

### B3. 部署到公网 **[你做]** ⏱ 1-2 小时

按 [03 · 部署到公网](./03-部署到公网.md) 走。流程概览：

1. 服务器装 Python 3.13 + Nginx
2. 上传代码，建虚拟环境，装依赖
3. 配 `.env`（这一步填 Supabase 连接串和百炼密钥）
4. 配 systemd，让服务开机自启、崩溃自动重启
5. 配 Nginx 反向代理
6. 配 certbot 上 HTTPS

**为什么要上 HTTPS**：Android 从 API 28 开始默认禁止明文 HTTP 请求。我们的 debug 包配了宽松策略所以能用 HTTP，但 release 包必须走 HTTPS，否则所有网络请求直接被系统拦掉。

**没域名怎么办**：certbot 需要域名才能签证书。临时方案是用 `nip.io` 这类泛解析服务——假如服务器 IP 是 `1.2.3.4`，直接用 `1.2.3.4.nip.io` 当域名，它会自动解析回这个 IP。演示够用，但不是长久方案。

### B4. 打最终交付包 **[你做]** ⏱ 30 分钟

```bash
cd "G:/workbuddy/任务路径/Fridge-Prophet/android"
export JAVA_HOME="G:\Android\jdk-17.0.20.1+1"

"G:/Android/gradle-8.14.5/bin/gradle.bat" clean assembleRelease \
  -PAPI_BASE_URL=https://你的正式域名/ \
  --console=plain
```

**装到真机上完整跑一遍九步链路。** release 包做了 R8 混淆，行为可能和 debug 包不同，这一步是最后的保险。

## 现在，从这里开始

**最简单的做法：在文件管理器里打开项目根目录，双击 `start-backend.bat`。**

「项目根目录」就是包含 `README.md`、`backend`、`android`、`tools` 的那个文件夹。
双击后会弹出黑窗口，自动完成建虚拟环境、装依赖、复制配置、打印局域网 IP、启动服务。
**不需要打开任何终端。**

<details>
<summary>用命令行的话（点击展开）</summary>

```bash
cd "G:/workbuddy/任务路径/Fridge-Prophet"    # 进入项目根目录
bash tools/start-backend.sh
```

`start-backend.bat` 和这条命令做的事完全一样，只是省掉了「打开终端、cd 到目录」两步。

手动分步执行：

```bash
cd "G:/workbuddy/任务路径/Fridge-Prophet/backend"

# 1. 建虚拟环境 —— 这一步不能省，否则 uvicorn 根本没装
C:/Users/Atao/.workbuddy-ai/binaries/python/versions/3.13.12/python.exe -m venv .venv

# 2. 装依赖
.venv/Scripts/python.exe -m pip install -r requirements.txt

# 3. 复制配置（零配置即可运行）
cp .env.example .env

# 4. 跑测试，确认 251 项全过
.venv/Scripts/python.exe tests/test_e2e.py

# 5. 启动
.venv/Scripts/python.exe run.py
```

**注意不要用系统的 `python run.py`。** 系统 Python 里没装这些依赖，
会直接报 `ModuleNotFoundError: No module named 'uvicorn'`。
必须用虚拟环境里的那个解释器（`.venv/Scripts/python.exe`）。

</details>

启动后打开这个地址：http://127.0.0.1:8000/docs —— FastAPI 自动生成的交互式接口文档，
所有接口都能直接在网页上点着调试，不用装 Postman。

**服务窗口不要关**，关掉服务就停了。按 `Ctrl+C` 停止。
